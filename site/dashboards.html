Dashboards

The interface around the charts: canvas, grid, status colours and the parts every dashboard page is made of. The same rules ship as a stylesheet for the web and a theme for Power BI.

Where this fits

A dashboard needs two kinds of rules. The style guide decides how the data is shown: chart choice, titles on live data, colour that survives filtering, data states. This page decides everything around it, and how to build it. When the two disagree about a chart, the style guide wins.

Canvas and grid

One canvas size, one grid. 1920 × 1080, sixteen columns of 102px, a 24px margin and a 16px gutter. Every visual starts on a column and spans whole columns. Type coordinates in; never drag.

Status colours

Five statuses, each with one colour, one sign and one word. A status is always a square marker with the sign inside and the word beside it, never a colour on its own.

  • The sign is drawn in ink on the colour (white on Baltic and Cherry, black on Jasmine, Sky and Steel), so the light colours keep their contrast.
  • Cell tints (--status-*-bg) are for table cells and badges. Use the tint or the marker, not both.
  • The status colours are also data colours. A chart encodes status or categories, never both. On a page with status, draw category charts in colours that aren't status colours: Teal and its ramp, Coral, Violet or Blush, with Steel for context.
  • Completed is Sky rather than a second blue: it stays distinct from On track for every common type of colour blindness (worst case ΔE 29).

Type

IBM Plex Sans on the web, Calibri in Power BI. Power BI only renders fonts installed on the viewer's machine, and Calibri has the lining, tabular figures the style guide asks for. No Newsreader on a dashboard: one typeface, hierarchy by size and weight.

Note

"What changed", an explanation, or a warning. The Callout pattern: a rule above and a mono key with a coloured square. No left border, no box.

What changed in Q3Water moved from watch to on track after the Q2 supply delays cleared.
Partial periodQ4 has 30 of 92 days. Totals will rise.
Not refreshedThe finance data didn't load. Last good refresh 27 Oct, 06:00.

Notes that depend on the data come from the data: a table of notes by item and period, picked by the same filters as the page. A typed note is true until the next refresh.

A refresh warning goes in one place: one tile, or one line under the header. The same message twice on a screen reads as two problems.

Table

Ruled, not filled. A bold header over a dark rule, hairlines between rows, a 2px rule over the total. A table is a full visualisation: use one whenever readers need to check, copy or forward the numbers.

  • Numbers right-aligned, tabular figures; text left-aligned.
  • Sort by value, not alphabet, unless the rows have their own order: periods, levels, statuses.
  • Fixed column widths. Automatic widths jump on every filter change.
  • A missing value is a dash, not a zero.

Footer

One line at y 1032: source, the date the data refers to, and when it was refreshed. Always there, always from the data, so a screenshot pasted into a memo still says what it shows.

Power BI theme

ren-data.theme.json sets the data colours in order, Calibri at every text size, white tiles with a 1px hairline and no shadow, 3px corners, 16px padding, ruled tables, coral buttons, underline page tabs and the canvas colour. Apply it first, before any visual exists: a theme doesn't override formatting a visual already has.

The theme can't setSo you
Positions and sizesType them in from the grid. Every row ends at 1896
Conditional formattingSet status colours per visual, from a measure that returns a hex code from the status table
Category colours by valueStore each category's colour in a column and apply it with conditional formatting, so filters don't reshuffle colours
Header, rail, notesBuild them from shapes and text boxes, group them, and copy the group to each page
Data bars, sparklines, target linesSet per visual. Data bars run from 0 to the target, never automatic
Alt textWrite one sentence per visual: what it shows and what it means

Before you publish

  • Every visual starts on a column and every row ends at 1896.
  • Four KPI tiles of one variant, each with a comparison.
  • Every status has a colour, a sign and a word.
  • Header period line, footer and notes come from the data. Nothing typed that will go out of date.
  • Test the opening view, the deepest single selection, a selection with no results, the first and the latest (partial) period, a reader without access, and a screenshot without context.
  • Alt text on every visual. Fixed column widths on every table.
  • No colour typed in by hand that belongs in the theme. If you need one, the theme is missing a case.
